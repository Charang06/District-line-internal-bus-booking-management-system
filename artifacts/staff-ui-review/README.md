Implemented locally on `ui/staff-page-handover`. Changes remain uncommitted. No merge or deployment was performed. The pre-existing working tree, including earlier typography and security work, was preserved.

## Scope and remaining limits

No backend source, API definitions, authentication/authorization, permission names or enforcement, username/password policy, MFA, rate limiting, schema, migration, RLS/grants, backup configuration, environment variables, Trip Controls logic, or booking/cargo/finance logic was changed by this task. Existing frontend calls and payloads remain; only viewing permissions no longer offers immediate mutation controls.

No failing UI checks remain in the tested paths. Live API/database integration, physical mobile devices and manual screen-reader checks were not exercised.

Code-review note about preserved behavior: bus registration and an optional mobile contact still use two separate existing API calls. If registration succeeds but contact saving fails, the bus can already be saved while the dialog reports the contact error. That pre-existing partial-save/retry behavior was left unchanged to respect the business-logic/API restriction; the optional-contact failure combination was not part of the mocked success/failure checks. No production records were used to test it.

The existing browser harness dependencies (`scripts/security/browser-local.cjs` and `artifacts/ui-refresh-review/browser-check.cjs`) were reused without modifying their source.
